# Streamlit to web capability parity

Parity is **not proven**. Keep Streamlit as a temporary reference; this audit does not recommend deleting it or certify Goal 1 complete. The web application exposes part of the legacy FEMTO workflow, but lacks the signal views, artifact browsing, several evaluation views, and the universal/cross-dataset workflow.

This is a source-level inventory, not a browser or deployment acceptance test. Evidence is the current implementation, not comments promising future functionality. No scientific metrics are reproduced here. Existing artifact availability determines whether artifact-backed views can run.

## Evidence and status key

- **D**: [dashboard.py](../src/bearing_pdm/dashboard.py), principally `main()` and its `VIEWS` branches. Its seven sidebar views are called tabs below.
- **C**: [dashboard_cross.py](../src/bearing_pdm/dashboard_cross.py), `render_universal()` and `render_validation()` plus their helpers.
- **A**: [api.py](../src/bearing_pdm/api.py). Routes below are local API paths; `vercel_app` mounts the same app under `/api`, imported by [api/index.py](../api/index.py).
- **W**: [frontend pages](../frontend/src/app), [API client](../frontend/src/lib/api.ts), and [SiteNav](../frontend/src/components/SiteNav.tsx). Current pages are `/`, `/upload`, `/degradation`, `/predict`, and `/evaluation`.
- **Covered** means the indicated behavior has an implementation on both sides, not that runtime parity has been certified. **Partial** means data or part of the interaction exists. **MISSING** means no equivalent route/page was found. Each partial or missing capability below remains an acceptance gap unless explicitly resolved by the supervisor's scope decision.

## Blocking gaps and acceptance boundary

Full parity is blocked by missing artifact/bearing/recording navigation; real waveform, temperature, FFT and feature displays; selected-point/baseline/truth and held-out RUL review; legacy HI comparisons; omitted evaluation plots, hidden-set and HI reports; incomplete architecture/methodology limitations; and the universal routing, quality, applicability, uncertainty and cross-dataset validation workflows. API-only metric availability does not close a missing web presentation. Single-file inspection does not establish dataset adaptation, feature extraction, model compatibility, or end-to-end upload-to-prediction parity.

Retain the D11 FEMTO-only cached-model gate. Reuse adapters, profiler, features, health, stages, routing, applicability and uncertainty when implementing missing capabilities. Preserve source sampling metadata, units, censored labels, causal versus retrospective distinctions, and held-out provenance. Never put raw sensor values in logs or publish private source locations. Safety checks added by the API should remain even where the reference dashboard was more permissive.

The web source path uses FastAPI and the typed HTTP client rather than importing or embedding Streamlit. That separation alone is not proof of production readiness or equivalent functionality. `GET /predictions/history` is an additional API-only in-memory history feature, not a replacement for any missing review tab. Final acceptance needs independent runtime comparisons on the same artifacts, missing-artifact and domain-refusal checks, and frontend/backend integration evidence. This documentation task leaves that acceptance to the supervisor and keeps Streamlit available as the reference.
