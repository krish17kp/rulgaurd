## Known limitations (say these proactively, don't wait to be asked)
1. College's `rul_seconds` label is defined from the known final timestamp (uncensored run) - its "naive" baseline scores a trivial 0.0 MAE by mathematical construction, not a real predictive result (`docs/decisions.md` D10). Only the `extra_trees` college numbers (~117k-132k s MAE, ~33-37h on a ~128h run) are meaningful.
2. College feature batch is a 1-in-5 representative sample (4030/4030 possible rows from 26/129 files), not the full run - a background full-129-file job was killed by the environment twice; the windowing code itself was independently verified correct on the real first and last file (M2 evidence).
3. Per-acquisition HI monotonicity is low (0.01-0.02) - trend correlation (which the HI selection is based on) is the meaningful metric, not sample-to-sample monotonicity.
4. HI and RUL models shown on the dashboard are FEMTO-only (fit exclusively on the 6 learning bearings) - the dashboard explicitly refuses to apply them to college data (D11) rather than showing a silently-wrong number.
5. No uncertainty interval on the RUL point estimate yet.
6. `Full_Test_Set` hidden-RUL scoring hasn't been run - the frozen pipeline exists (`artifacts/models/rul_*.joblib`) but hasn't been evaluated against the hidden continuation.

## Likely faculty questions and evidence-based answers
- "Is this leakage-safe?" -> Yes: leave-one-bearing-out for FEMTO (whole bearings held out, `assert_no_leakage` guard), chronological expanding-window for college (`docs/data-contract.md`, `evaluation.py`).
- "Why does the naive college baseline show 0 error?" -> It's a mathematical identity from the label definition, documented as D10, explicitly flagged as not-a-real-result on the dashboard itself.
- "Does the model diagnose the fault type?" -> No, explicitly a non-claim (`docs/prd.md`); this is RUL regression + a secondary stage indicator, not fault diagnosis.
- "Is the RUL number a real prediction or memorized?" -> The dashboard's frozen-pipeline number is fit on all 6 bearings (near-perfect on Bearing1_1 because it was in training); the honest generalization estimate is the LOBO table in the Model Evaluation tab (extra_trees MAE ~5061s, beats naive on 4/6 held-out bearings).
- "What about the hidden Full_Test_Set?" -> Not scored yet by design - the pipeline is frozen but hidden-set scoring is a deliberately separate, later step to avoid any temptation to peek during development (`docs/data-contract.md`).
